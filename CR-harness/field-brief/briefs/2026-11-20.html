1 · MANGO Arena: failed calls hid inside the metric, and same-seed reruns did not agree

watch arXiv:2611.23613 (submitted 17 Nov 2026; Amar). The authors built an open-source testbed in which four LLM agents each run one company in a serial supply chain adapted from MANGO, a classroom factory-management game. The environment enforces hard rules (a truck limit, a no-credit cash constraint and production capacity), logs every blocked attempt to break them, and gives agents a public message board on which side payments are explicitly forbidden. In a pilot with three small reasoning models, two scripted reference policies, two conditions (with and without a supplier fire) and three demand seeds, all LLM agents amplified demand variability as it moved upstream, by 7 to 25 times at the Retailer and 13 to 179 times at the Supplier, largely by ordering in batches. Real rule violations were rare (at most 7 of 288 decisions per model) and no agent proposed a money side deal. The pilot’s main lesson is about evaluation: API failures (rate limits and runaway hidden reasoning) entered the metrics silently as “no order” decisions, and rerunning games with the same seeds and no failed calls changed upstream bullwhip by up to 17 times. With three seeds, conclusions about how a disruption affects a given model did not survive a rerun.

For CR: CR evals also turn a model call into a game move. A failed or timed-out call must be logged as a failure, never as a legal no-op or default action, and a result built on three seeds should be rerun before it is believed.

Suggested next step: In CR eval reports, count failed / timed-out calls separately from chosen no-op or wait actions, and rerun one headline comparison with the same seeds to measure run-to-run spread before quoting a difference.

2 · Idempotency is not recovery: suppressing duplicates is different from knowing what happened

watch arXiv:2611.23353 (submitted 17 Nov 2026; Xu). When a language-model agent’s tool call is interrupted, the action may already have changed an external system without confirmation; retrying risks duplication, and assuming success may conceal an action that never occurred. The author studies these failures in a controlled agent runtime that combines authorization, an action ledger, target-side idempotency, reconciliation and evidence sealing, injecting ten single-host fault classes and comparing four configurations and three ablations against a target-side oracle that is separate from the runtime ledger. On each of Windows and Linux, 7,513 trials used 96 captured model responses from 24 constructed cases. In 200 known crash-and-replay pairs, the full configuration recorded 0/200 repeated effects versus 117/200 for each simpler baseline. A ledger ablation had 170/170 orphaned effects (versus 0/170) and 200/300 recovery successes (versus 300/300). Disabling reconciliation left 100/100 known post-effect crash outcomes ambiguous despite no observed duplicates. The full runtime had about one-seventh of fail-open throughput, and injected evidence-write faults left 75/100 trials per platform unresolved. The author limits the claims to the tested benchmark.

For CR: When a CR runner or watchdog restarts mid-turn, "don't send the action twice" is not enough: the runner must also be able to tell whether the action reached the engine. That needs a pending-action ledger and a check against engine state, not just a dedupe key.

Suggested next step: For the CR action path, write a pending entry before dispatch and reconcile against engine state after any crash or timeout; in a replay, kill the runner between dispatch and acknowledgement and count duplicated, lost and ambiguous actions.

3 · State-transfer auditing: the failures happen where state moves, so record those moves

watch arXiv:2611.23346 (submitted 17 Nov 2026; Shah, Kathrotia). Long-horizon agents across codebases, browsers and infrastructure rely on an execution harness to move state between the working context, session history, persistent memory and the external environment. Conventional traces log prompts and tool calls, but the authors argue critical failures occur during state transfers: a transfer can admit unchecked content (indirect prompt injections, unverified memory writes), rewrite state lossily (context compaction dropping user constraints, memory consolidation stripping source authority) or restore state incompletely (workspace rollbacks leaving aborted cache state active on the inference server). They present a state-transfer audit architecture: at each boundary an audit point specifies the minimal hash-chained record the harness emits, separating low-overhead deterministic checks from model-based semantic checks. They argue the same records needed for causal failure attribution also supply the durable state for runtime controls — least-privilege capabilities, replay-resistant authorization outside the prompt, information-flow control, obligation monitors and transactional recovery. A reference middleware evaluated across 240 multi-step fault-injection trajectories is reported to localize root causes and catch cross-transfer violations missed by lifecycle and tool-only logs, at microsecond deterministic overhead.

For CR: CR traces already record observations and actions; the risky moments the paper names — compaction that drops a rule, a memory note that loses its source, a restore that leaves stale state — are exactly where a CR run could silently change what the agent was allowed to do.

Suggested next step: Add a hash-chained record at the CR summary/compaction step and at any state restore, and check in replay that the frozen rule text and legal-action contract are byte-identical across each transfer.

4 · Reversibility classes: whether an action can be undone is a property to declare and test

watch arXiv:2611.22075 (submitted 17 Nov 2026; Waghmare, Sufi). Tool-using agents change files, databases, access rights and public information, yet permission to call a tool does not establish whether a mistake can be undone. The authors present Reversibility Classes, a declared five-level vocabulary with argument-sensitive rules, conservative defaults and an explicit prior-state capture contract. The pinned implementation and evidence-linked registry cover 536 tools across 20 MCP servers. All 738 rule-case checks conform to declared expectations, while native annotation mapping differs from draft registry labels for 118 of 481 comparable tools. One AI-assisted reviewer approved 148 ratings, 75 matching the registry, which the authors note is not independent agreement. On 2,158 recorded runs, the session guard gates the associated action in all 29 attributable attack-positive runs, compared with 18 for a read/write proxy, while adding nine approval points across 1,209 benign runs. Controlled file, Git, SQLite and three-browser experiments show that recovery depends on captured state, later changes, editor storage and recovery route, and expose a Git merge-state exception. The evidence supports making recovery assumptions explicit and testable; it does not establish registry-wide accuracy, reduced production harm or general recovery reliability.

For CR: The fleet's GREEN / YELLOW / RED gate is a reversibility judgement made by hand. A declared, argument-sensitive class with "capture prior state first" as a contract is a way to make that judgement testable for CR tooling and bot actions, and shows a read/write split misses cases.

Suggested next step: Tag the CR harness's own side-effecting tools (writes, pushes, engine resets) with a reversibility class and the prior state each must capture, and check one recorded run where a read/write split would have let an irreversible action through.

  • AHE-Beta (submitted 18 Nov 2026): a requirement-centred harness-evolution loop (simulated users raise requirements as issues, team-based changes, merge only on a verified requirement plus review); reported pass@1 21.9% → 33.3% on held-out tasks with 40.8% fewer tokens, and 31 of 48 blind human A/B pairs preferred. Sits next to the 18 Nov self-improving-harness card; not carded to avoid a second harness-evolution card in a row.
  • Beyond Weight Updates (submitted 19 Nov 2026): evolves the harness (prompt, tool schemas, skills, planning scaffold) with GEPA while the policy stays frozen; reported to recover most weight-update gains at a fraction of compute on SWE-bench Verified, OfficeBench and Terminal-Bench. Same theme as above.
  • Tracking Representations in LLM Reasoning Traces for Iterated Games (submitted 17 Nov 2026): interpretability study of LLM agents in iterated incomplete-information games; once a model commits early to a wrong belief about the game it rarely recovers, visible in both trace and activations. Interesting for CR belief tracking, but no harness-side method yet.
  • Done, But Still Working (submitted 17 Nov 2026): anytime evaluation of when coding agents should stop, by replaying about 6,000 recorded runs; stopping after the same patch passes twice saved 23% in a preregistered replication, but non-inferiority on quality was not established. Relevant to the fleet's coding loop more than to CR.
