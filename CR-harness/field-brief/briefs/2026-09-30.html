1. Upstream messages override correct answers watch

What it is. Gong, Zhang, Gao et al., arXiv:2609.36855 (submitted 29 Sep 2026). A controlled study of message passing between LLM agents: five benchmarks, five receivers, task and evidence held fixed, three conditions (no message, the upstream’s message, a message with the opposite conclusion).

Evidence. Messages often help when the receiver would otherwise be wrong. When the receiver would have been right, an incorrect upstream message changes its answer in up to 32% of cases, and in 94% of audited harmful cases the receiver copies the upstream’s specific wrong answer (“answer substitution”). Removing unreliable messages recovers part of the lost accuracy.

Why it matters for CR. A second independent result (after the 09-25 debate-collapse paper, arXiv:2609.26145) that showing a peer’s conclusion can destroy a correct independent judgement. It supports blind dual-LGTM and argues that planner→executor chains in multi-agent CR designs should pass evidence rather than conclusions unless upstream reliability is known.

Suggested next step

  • In the dual-LGTM protocol notes, keep seats blind and have a handoff pass evidence pointers, not verdicts.

2. CRJudgeBench: judge the review comment, not just the code watch

What it is. Pan, Li, Zhang et al., arXiv:2609.37216 (29 Sep 2026); dataset on Hugging Face. 1,199 instances from real pull requests and expert-verified perturbations, covering trustworthy and plausible-but-untrustworthy review comments.

Evidence. Sentinel, a repository-grounded agentic judge that gathers code evidence before judging (trained from Qwen3-Coder-30B-A3B), gets 76.60% on the 359-instance test set: +6.13 points over GLM-5.3 and +19.78 over its base. The authors conclude that even strong general LLMs struggle to spot untrustworthy comments.

Why it matters for CR. Fleet reviewers can be confidently wrong. A finding should count only if it carries a code-evidence pointer that a judge (or the other seat) can verify. This also applies when reviewing CR cockpit/eval PRs.

Suggested next step

  • Require an evidence pointer (file:line or test output) on every blocking review finding; sample a few past findings and check whether they would have passed.

3. Executable-contract audit: scores can rest on defective tools watch

What it is. Bellibatlu, Wang, Zhang et al., arXiv:2609.37315 (29 Sep 2026). Each tool’s advertised interface is treated as an executable contract; the implementation and the evaluator’s provenance are checked against it.

Evidence. Across 34 audited mutating tools in four benchmarks it confirms seven tool defects and one evaluator property. On injected defects the checker raised no false positives in 25 flags but missed most; in 29 of 33 scored misses a clause covered the defect but no probe revealed it. The clearest case is a clinical benchmark whose tool says a write executed under a no-write design its interface doesn’t disclose, so the grader measures whether the request carried the expected payload, not whether any record changed.

Why it matters for CR. CR’s ETL scores what the sim reports. If an accepted deploy doesn’t actually change sim state (or a rejected one does), the metrics are wrong in a way every rerun repeats.

Suggested next step

  • Write a small probe set for the sim’s action-result contract: after each accepted action, assert the state change; after each rejected one, assert no change. Trace two headline metrics back to state the sim wrote.
