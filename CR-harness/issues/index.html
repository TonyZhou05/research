How to propose a PR (repo norms)

Aligned with docs/CONTRIBUTING.en.md in the private repo:

  1. File a GitHub issue describing the ask (a one-line title is enough). Do not open a PR first.
  2. Hand the issue link to the AI implementer (Claude Code). It creates a branch, posts a plan comment on the issue, waits for a human “confirmed / go ahead”, then implements, tests, and opens the PR — posting the PR link back on the issue.
  3. Human review on the PR (Approve / Request changes / Comment). Prefer gh pr merge <n> --squash after review. Merging is not hard-gated on the free private plan — wait for review before merging.
  4. You usually do not create the branch or open the PR yourself; watch the issue as the single entry point.
